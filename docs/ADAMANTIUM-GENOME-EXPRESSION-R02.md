# Adamantium Genome R02 — signed artifact closure and structural self-host proof

Status: **draft, source-only, headless**. The already-running AdamantiumToolBox and JediControl installations are unchanged.

## Boundary: genotype ≠ executable phenotype

R01 canonically encodes a G0 Universal Graph in typed structural / interface / connection genes. R02 adds a *verifiable expression prerequisite*: a signed manifest mapping every versioned capability type referenced in the genome to a content-addressed artifact blob.

Actual runtime loading, deployment, service authorization, credential recovery, Noosphere state, and native code compilation remain independent responsibilities. There is no remote installation, automatic genome promotion or runnable self-reproducing process in R02.

## Verification pipeline

1. The trusted caller supplies an R01 original genome plus the **externally pinned** trusted Ed25519 public key(s). Trust roots do not come from the genome.
2. `verifySignedArtifacts` reconstructs and structurally validates the genome, checks the complete required capability type closure, version and platform compatibility.
3. The signed manifest uses a domain-separated SHA-256 canonical payload. Ed25519 verifies its signature. No unsigned extra or omitted capability may be accepted.
4. Every referenced blob must already exist in the caller-provided Map; R02 hashes its actual bytes and checks the claimed length. There is no fetching, decoding or invocation.
5. The output receipt attests **signature + bytes** only; `authorized:false`, `executable:false`, `verifiedNativeCompiler:false`, `verifiedPolicy:false`. It cannot be used as an execution grant.
6. `proveStructuralSelfHosting` additionally requires a versioned GENESIS compiler-type node and signed artifact, rebuilds two consecutive generations of the graph-genome representation, and checks identical canonical graph hashes.

## Three kinds of proof that must not be confused

| Level | What is proven | Status |
|---|---|---|
| A — codec fixed point | Genome → graph → genome repeated gives the same typed graph | Implemented / CI |
| B — binary reproducibility | Real GENESIS compiler N builds compiler N+1, then N+1 builds N+2, with identical signed executable bytes | **Not implemented** |
| C — phenotype equivalence | N+1 passes isolated behavior, performance, resource compatibility, independent policy and rollback tests before activation | **Not implemented** |

Level A is useful for validating the self-description, but **does not establish true bootstrapping or semantic equivalence**. R02's fixture artifacts are deliberately simple test bytes, not compiled GENESIS executables.

## Trust and resource constraints

- Ed25519 only. Private keys exist in test memory only; production signing occurs outside the runtime in an independently managed artifact supply chain.
- Each artifact is ≤32 MiB, combined verified byte budget ≤64 MiB, up to 1024 exact typeRefs; graph size is governed separately by G0/R01 limits.
- Strict platform pinning to a portable or explicitly requested host target; no silent migration to another host or GPU assumption.
- Graph composites currently require a separately verified transitive graph catalog; R02 rejects them rather than guessing missing modules.
- The existing G0 C++17 compiler remains mandatory for cross-graph recursion and instant-cycle checks. R02's JSON shape checks are not a substitute.
- A matching SHA-256 hash is not identity or authorization. Ed25519 binds the manifest to a configured key, but application trust still depends on operator-controlled key policy.
- No artifact paths, private host names, arbitrary URLs, credentials, downloaded binaries or code execution are accepted.
