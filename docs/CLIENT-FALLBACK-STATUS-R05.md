# Client fallback status R05 (backend-only)

Goal: make an approved owner SSH transport useful when the optional
JediControl desktop/broker path is unavailable. This is a **read-only
command**, not a new frontend, external MCP gateway or shell bypass.

## Contract

`tools/windows-client-status.ps1` reads only bounded user-private
`session-status.json` and `transport-status.json` generated by the
client observers. Paths are under `%LOCALAPPDATA%` by default, or
supplied with an absolute `-Root` for tests.

The command emits a compact `mas-client-status-1` JSON object:
`overall`, `observedUtc`, `host`, `session.mode`,
`session.agentCount`, `transport.mode`, `transport.probeOk`.
It whitelists fields, rejects invalid/symlink/oversized snapshots,
and treats stale or future-dated telemetry as degraded.

`local_signals_healthy` means the two local observations agree,
**not** that the broker has authenticated this client or approved
remote input. `controllerAuthorization` always says
`not_verified`. The server-side operator-authorized device
status/lease check remains mandatory before input, UAC or writes.

`-Strict` exits with code 2 on degraded local signals. Without it
the tool returns JSON for diagnosis rather than a remote mutation.

## Operator-controlled SSH route

1. Verify the remote OpenSSH host fingerprint matches a previously
   pinned key and that the login identity is authorized.
2. Keep the SSH alias, key path and current routed IP in a **private**
   configuration on the managing node. Never commit host, VPN identity,
   token, SSH key or absolute device path to this repository.
3. Use a no-PTY, pinned-host, publickey-only, no-forwarding session.
   Run the status script with an ordinary non-elevated Windows user.
4. Preserve existing JediControl emergency latch, controller lease,
   consent prompts and DPAPI tokens. SSH diagnostics do not authorize
   privileged intervention or desktop control.
5. If the SSH route and JediControl both fail, report the outage; do
   not disable host-key verification, expose RDP or install new
   credentials blindly.

## Verified boundaries

Two independent observer tasks can report fresh session/transport
telemetry while leaving the existing JediControl tunnel and agent
running. Direct SSH login to the owner laptop was proven using an
already approved key and pinned server identity; that is independent
from the JediControl broker, but still depends on the network route
and existing connected management bridge.

The CI fixture checks fresh, stale, redacted and strict-fail cases.
Real tunnel failure, laptop power loss and authenticated operator
failover require separate acceptance. Workstream: issue #176.
